# 7.4 — Studio document bar and master–detail

## Context

`studio_config_panel.dart` is a single `ListView` holding thirteen
concerns, in this order: Copilot card, template chips, region chips,
section reorder list, reset/save buttons, headline, summary, work
history, projects, skills, education, hobbies, publications, references.
All of it inside a column clamped by `studio_view.desktop.dart` to
380–676px.

This is the root cause behind most of the review's other findings.

**Mixed altitude.** Template and region are chosen once per CV and then
never touched, yet they permanently occupy the top of the scroll, above
the bullet-level edits that are made constantly.

**No anchor.** Section visibility lives at the top, a given bullet lives
two thousand pixels down, and there is no way to see both or to get back
except scrolling.

**Four levels of nesting in the narrowest column on screen.** Category →
entry → bullet sublist → inline editor, each indenting. By the time you
are editing bullet text you have roughly 300 of your 380px, while
1,100px sits unused to the right. The panel is capped at 676px on the
theory that extra width is better spent on the panel than the preview —
correct instinct, but the cap means a 3440px display spends the surplus
on nothing at all.

The fix is a pattern this repo already owns and already trusts.

---

## The pattern already exists

`vault_view.desktop.dart` is a `Row` of a card list (`flex: 3`) and an
editor panel (`flex: 4`) that appears when something is selected.
`VaultViewModel.openTarget`/`openId` hold which one, and
`vault_editor_panel_router.dart` is a single `switch` resolving target to
panel — with a doc comment stating exactly why it is centralised:

> Kept in one place so desktop/tablet/mobile layouts don't each
> reimplement this switch.

Studio should be the same shape. Better still, Studio's master list
already exists — the "Sections" reorderable checkbox list — and
`CvSectionType` is already the enum that would key the router. Vault
needed a bespoke `VaultEditorTarget` enum; Studio does not.

---

## Target layout

Four zones on desktop, replacing two.

```
┌──┬──────────────────────────────────────────────────────────┐
│  │ Template ▾  Country ▾  2 pages          Export PDF       │  document bar
│  ├─────────┬──────────────────────┬─────────────────────────┤
│  │ Sections│ One section's items  │  Preview                │
│ra│ ☑ Summ. │                      │  (capped at printed     │
│il│ ☑ Skills│  full width for      │   width, 7.3)           │
│  │ ☑ Work  │  bullets + editing   │                         │
│  │ ⋮ drag  │                      │                         │
└──┴─────────┴──────────────────────┴─────────────────────────┘
```

- **Document bar** — set-once configuration lifted out of the scroll,
  plus the page count from 7.3 and Export moved off its floating button.
- **Section nav** — the existing reorderable list, now doing three jobs
  instead of two: include/exclude (checkbox), order (drag), and *which
  section is being edited* (selection). Short, fixed, always visible.
- **Section editor** — only the selected section's items, at real width.
  This is where the 1,100px goes.
- **Preview** — unchanged from 7.3.

The Copilot card is the one thing that does not obviously belong to any
zone. It is per-draft, set-once-ish, and tall. Put it in the section nav
column below the section list rather than in the bar — the bar should
stay one row, and a text area does not fit in one row.

---

## Decisions locked

| # | Decision | Rationale |
|---|---|---|
| 1 | Selected section lives on the ViewModel, not widget `State` | Direct precedent: `VaultViewModel.openTarget`. It also has to survive the compact layout's drill-down navigation, which widget-local state in one pane would not. |
| 2 | Key the router on `CvSectionType`, no new enum | It already enumerates exactly the eight sections, already has `displayLabel`, and is already what `sectionOrder` and `sectionHasData` speak. A parallel `StudioEditorTarget` would need keeping in sync for no gain. |
| 3 | A section editor per section type, in `lib/features/studio/widgets/sections/` | Mirrors `vault/widgets/*_editor_panel.dart`. Eight small files beat one 400-line switch body, and it is the only way the summary/headline/references editors stop being special cases. |
| 4 | `studio_config_panel.dart` is **deleted**, not refactored | Its content becomes the document bar, the nav, and eight section editors. Keeping the name for one of the three would mislead about what it now holds. |
| 5 | Compact stays tabbed, with the nav as a drill-down | Two tabs (Configure / Preview) still; Configure becomes nav → editor with a back affordance, not three tabs. Three tabs would put the preview two taps from the thing changing it. |
| 6 | **Do not split `StudioViewModel` in this step** | It is 737 lines and carries `// --- skills ---` style banners that `CLAUDE.md` explicitly calls out as a sign a file wants splitting. Both true, and both a separate change — doing it inside a layout restructure means a diff nobody can review. |
| 7 | No golden test for `StudioView` | See "Why no golden" below. This is a deliberate exception with a stated reason, not an omission. |

## What changes

### New — `lib/features/studio/widgets/studio_document_bar.dart`

```bash
stacked create widget studio_document_bar --no-model \
  -c stacked_configs/studio.json
```

One row: template picker, region picker, page count (7.3), Export.
Replaces `studio_draft_header.dart`'s job as well — that widget currently
puts the draft name hard left and its edit pencil hard right with 1,500px
of nothing between them on a wide display, which the review flagged
separately. Fold the name, the back link and the edit affordance into the
left end of this bar and delete `studio_draft_header.dart`.

The pickers stay as-is (chips) in this step. **7.5 replaces them** with a
gallery and a searchable field — which is the whole reason this step
comes first: the new pickers get built once, in their final home.

### New — `lib/features/studio/widgets/studio_section_nav.dart`

The existing `ReorderableListView` block, extracted, plus a selected
state per row and an `onSelect` callback. Three affordances on one row
needs care: the checkbox is include/exclude, the drag handle is order,
and the row body is select-for-editing. The drag handle already exists
and is already separated via `ReorderableDragStartListener`; the
checkbox already has its own hit target. The row body is the new one.

Keep "Reset to my default" / "Save as my default" at the bottom of this
column, and while here, address the review's note that they are two
similar-looking 12px purple text buttons side by side of which one is
destructive — separate them, and make the wording asymmetric.

### New — `lib/features/studio/widgets/studio_section_editor_router.dart`

A `switch` on the selected `CvSectionType` returning the right editor,
modelled on `vault_editor_panel_router.dart` including its doc comment's
reasoning. Returns an empty-state widget for `null` (nothing selected)
and for a section with no data.

### New — `lib/features/studio/widgets/sections/*.dart`

Eight editors. Most are thin — they wrap what
`studio_config_panel.dart` already builds:

| Section | Content | Source today |
|---|---|---|
| summary | `StudioFieldOverrideCard` | existing, unchanged |
| skills | `StudioSkillSelector` | 7.2, unchanged |
| experience | `VaultItemSelectorList` + bullets | existing, now full width |
| projects | `VaultItemSelectorList` + bullets | existing |
| education | `VaultItemSelectorList` + tailorable | existing |
| hobbies | `VaultItemSelectorList` | existing |
| publications | `VaultItemSelectorList` + bullets | existing |
| references | `StudioFieldOverrideCard` | existing |

Headline has no `CvSectionType` of its own — it prints in the header, not
a section. Put it in the document bar's overflow or alongside the summary
editor; do not invent a fake section for it.

`VaultItemSelectorList` should need **no changes** — it was always
width-agnostic; it was the column around it that was narrow. Worth
confirming rather than assuming, since its bullet sub-list indents by
`paddingDefault` per level and may want less indent now there is room.

### `studio_viewmodel.dart`

```dart
/// Which section's items the editor pane is showing. Null on open —
/// deliberately, so the first thing seen is the section list rather
/// than an arbitrary section's contents.
CvSectionType? get openSection;
void selectSection(CvSectionType? type);
```

Plus `pageCount` if 7.3 has not already added it.

`selectSection` should not persist. Which section you were last editing
is not part of the document, and restoring it on load would fight the
"start at the list" decision above.

### `studio_view.desktop.dart` and `.compact.dart`

Desktop becomes document bar + three-way `Row`. The existing
`_panelWidthFraction`/`_minPanelWidth`/`_maxPanelWidth` constants and
their doc comment go away — the reasoning they encode ("extra width is
better spent on the panel than the preview") is now handled by giving
the editor column the surplus and capping the preview at printed width
per 7.3. Replace with: nav column fixed (~220px, it holds eight short
labels), preview capped, editor takes the remainder.

Compact: document bar + tabs, Configure tab drills nav → editor.

## Why no golden

Adding a `StudioView` golden looks like the responsible move for the
largest layout change of the six. It is a trap. `StudioPreviewPane`
rasterises a real PDF through `PdfExportService` and `PdfPreviewCustom`;
a golden would either mock `render` to return bytes and then race the
rasteriser's async frames, or mock it to return nothing and pixel-test an
error state. Both produce a flaky baseline, and a flaky golden on a
`pull_request`-triggered CI is worse than none.

If pixel coverage is wanted here, the honest unit is a widget golden for
`StudioSectionNav` and `StudioDocumentBar` in isolation — no preview
pane, no PDF, deterministic. That is a reasonable follow-up and is not
required for this step. What *is* required is the browser pass below.

Confirmed: no golden currently covers `StudioView` or any widget under
`lib/features/studio/widgets/`, so nothing regresses by not adding one.

## Steps

Ordered so the app stays runnable throughout — no step leaves Studio
broken.

1. Extract `StudioSectionNav` from `studio_config_panel.dart` with no
   selection behaviour yet. Panel still renders everything below it.
   App works.
2. Add `openSection`/`selectSection` and the router, with only
   `summary` and `skills` wired. Panel still renders the rest below.
   Both paths visible at once, which is ugly but working.
3. Move the remaining six sections into editors, deleting each from the
   panel as it moves. The panel shrinks to nothing.
4. Delete `studio_config_panel.dart`.
5. Build `StudioDocumentBar`; fold in `studio_draft_header.dart` and
   delete it; move Export off the FAB.
6. Rework `studio_view.desktop.dart` to the three-column layout.
7. Rework `.compact.dart` for the drill-down.

Steps 1–4 are the substance. 5–7 are layout and can be judged visually.

## Verification

```bash
stacked generate
dart format .
flutter analyze
flutter test --exclude-tags=golden
```

**ViewModel tests** — `studio_viewmodel_lifecycle_test.dart` gains
coverage for `openSection` defaulting to null, `selectSection` setting
and clearing it, and (the one with real bug potential) selecting a
section then hiding it: the editor must not be left showing a hidden
section's items. Decide the behaviour deliberately — clearing the
selection is probably right — and test it.

The other three `studio_viewmodel_*_test.dart` files should be
**untouched**. If a pure layout restructure changes them, ViewModel API
has moved when it should not have.

**Goldens** — none affected, per above. Run `flutter test --tags=golden`
anyway before pushing; if a baseline moves, something reached into
`AppChrome` or the theme and this step should not have.

**Browser** — the real verification, at four widths:

- **1728px** — three columns; nav short and fully visible; selecting
  each of the eight sections shows the right editor; bullet text has
  visibly more room than before; preview unchanged from 7.3.
- **~1100px** — still three columns or degrades sensibly; the editor
  column does not collapse below usable width.
- **~800px (tablet)** — tabbed; Configure drills into a section and
  comes back.
- **~500px (mobile)** — same, single column, nothing clipped.

Then the round-trip that exercises the state: reorder two sections, hide
one, select another, edit a bullet override, switch template, and
confirm the preview reflects all five and a reload restores everything
except the selected section.

## Risks

1. **Scroll position across section switches.** Each editor is its own
   scrollable. Switching sections and back should not restore a stale
   offset from a different section's content. Give each editor a
   `PageStorageKey` or accept a reset — but decide, do not leave it to
   whatever `ListView` happens to do.
2. **The three-affordance nav row.** Checkbox, drag handle, and row-body
   tap in one row is a hit-target problem, especially on touch. If it
   feels ambiguous, the row body wins and the checkbox moves to a
   trailing position — but test it before assuming it is fine.
3. **Compact regression.** Tablet and mobile share one file today and
   get the least attention. The drill-down is new behaviour, not a
   reflow, and it has no test coverage of any kind.
4. **Scope creep into the ViewModel.** Decision 6 will be tempting to
   break once the file is open. Eight new editor widgets already make
   this a large diff.

## Not in scope

Splitting `StudioViewModel`; template and region picker replacements
(7.5); a global search; keyboard shortcuts. The last two both want the
document bar to exist first, which is the point of doing this step.
