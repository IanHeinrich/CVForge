# 7.7 — Settings

## Context

The original review gave Settings two lines in a table of small fixes.
That undersold it. Looking properly, Settings has one structural
problem, one thing that is arguably the most important safety gap in the
app, and a cluster of form-control inconsistencies that make it the
roughest surface in the product.

`settings_view.dart` is 42 lines: a `SingleChildScrollView` holding
`BackupSettingsCard` and `CopilotSettingsCard` with a gap between them.
Each card is a `Container` with `color: kcDarkGreyColor` — the same
value as the scaffold behind it, so neither reads as a card at all. The
two headings float on an unbroken ground with nothing indicating where
one concern ends and the next begins.

---

## Decisions locked

| # | Decision | Rationale |
|---|---|---|
| 1 | Give Settings a page header and a content max-width | It is the only top-level surface with neither. At 1600px its description paragraphs run to ~1,100px lines. |
| 2 | Backup gets a **state**, not just two buttons | See "The real problem" below. This is the substantive change in this file; everything else is tidying. |
| 3 | Add `errorText` to `AppTextField` | No field anywhere in the app can currently show a validation error, because the shared widget has no parameter for one. Settings is where that first bites, but 7.8 needs it more. |
| 4 | Replace bare `DropdownButton` with `DropdownButtonFormField` | Two unlabelled underlined dropdowns sit either side of an outlined, labelled `TextField`. Three controls, two visual languages, in one card. |
| 5 | Do **not** restructure Settings into tabs or a nav | Two sections. A settings nav for two sections is furniture. Revisit at five. |

---

## The real problem: backup has no state

`BackupSettingsCard` offers "Export backup" and "Import backup" and
nothing else. There is no record of whether a backup has ever been
taken, when, or whether the data has changed since. The card is a pair
of verbs with no nouns.

That matters more here than in most apps, because **everything lives in
browser IndexedDB and nowhere else**. There is no account, no sync, no
server — `CopilotSettingsCard`'s own copy says so proudly ("there is no
CVForge server"), and that is the right design. But the corollary is
that a cleared site setting, a new browser, a wiped profile, or a
private window takes the entire Vault and every CV with it, silently and
without warning.

This is not hypothetical. During this review the preview browser's Vault
emptied itself between sessions for reasons neither the reviewer nor the
author could identify — it happened to be example data, so it cost
nothing, and a single click restored it. With a real Vault behind it,
that same event is unrecoverable and the app would have given no
indication it was even a possibility.

What the card should carry:

- **When the last export happened**, persisted in `AppSettings`
  alongside the Copilot fields. "Last backed up 3 days ago", or "Never
  backed up" — which is the state most users will be in and the one
  worth saying plainly.
- **Whether anything has changed since.** `VaultService` and
  `DraftService` both already write on a debounce; a `lastModified`
  stamp is cheap and makes "12 changes since your last backup" possible.
  If a stamp per write is too invasive, a boolean dirty flag cleared on
  export is enough to say "you have unsaved changes since your last
  backup".
- **A prompt at the right moment**, not just a card in Settings nobody
  visits. After a first successful PDF export is the natural one — the
  user has just finished something worth keeping.

Deliberately **not** proposed: automatic cloud backup, or nagging.
Local-first is the product's position and should stay it. The ask is
that the app be honest about what local-first costs.

## Form-control inconsistencies

All in `copilot_settings_card.dart`, all visible in one screenshot:

| # | Issue |
|---|---|
| 1 | The provider dropdown is a bare `DropdownButton` — underlined, no label. Nothing says it is the provider. |
| 2 | The model dropdown is the same, also unlabelled. It reads "Claude Opus 5" with a price beneath and no indication it is selectable, let alone what it selects. |
| 3 | Between them sits an outlined, floating-labelled `TextField`. Two visual languages, one card. |
| 4 | The API key field stretches to the full content width — over 1,000px for a secret that is never that long, and one that is `obscureText` so the width buys nothing. |
| 5 | "Remember on this device" says nothing about the consequence. Stored where, in what form, and how to undo it? For an API key with real billing attached, that sentence is load-bearing. |
| 6 | Success is plain body text — "Connected." in the same style as everything around it. No colour, no icon, no dismissal. It also never clears. |
| 7 | The price label (`$5.00 in / $25.00 out per M tokens`) sits below the model with no explanation that it is the provider's price and not a charge from CVForge. |

Fixes are individually obvious: label the dropdowns, unify on the
outlined form language, cap the key field at a sensible measure,
expand the "remember" copy to name the storage and the risk, and give
the connection result a proper success/error treatment with a semantic
colour rather than body text.

Issue 5 deserves a sentence of real thought rather than a label tweak —
"Stored unencrypted in this browser. Anyone with access to this device
can read it." is the honest version, and the checkbox should probably
default off (confirm it does).

## What changes

### `lib/features/settings/views/settings/settings_view.dart`

Page header ("Settings", `titleLarge`) and a `ConstrainedBox` capping
content at ~720px, left-aligned rather than centred — a settings column
that drifts to the middle of a 3440px screen is worse than one anchored
where the nav rail already draws the eye.

Once 7.1 lands, both cards drop their `color: kcDarkGreyColor` and pick
up `surfaceContainerLow` from the theme, at which point they read as
cards for the first time. **This file's changes are best done after
7.1**, or the max-width fix lands on a surface that still looks flat.

### `lib/ui/widgets/common/app_text_field.dart`

Add `final String? errorText;` and pass it into `InputDecoration`. Two
lines, and it unblocks 7.8's date validation, which is the bigger user
of it.

### `lib/features/settings/widgets/backup_settings_card.dart`

The backup state above. Needs `AppSettings` to gain a `lastBackupAt`
field (`@freezed`, so `stacked generate` after) and `SettingsService` a
mutator for it — note that `SettingsService` currently has zero
mutators for some fields by design, per the Phase 4 shipped note, so
check that convention before adding one.

### `lib/features/settings/widgets/copilot_settings_card.dart`

The seven items above.

## Verification

```bash
stacked generate
dart format .
flutter analyze
flutter test --exclude-tags=golden
```

**ViewModel tests** — `test/features/settings/viewmodels/settings_viewmodel_test.dart`
already covers export/import and provider/model selection. Add:
`lastBackupAt` is null initially; a successful `exportBackup` sets it; a
failed export does not.

**Goldens** — `settings_view_default.png` **will** change, from the page
header alone. It is one of the three golden-covered Views, so this file
is unusual among the seven in having real pixel coverage. Dispatch
`update-goldens.yml` and commit the PNG in the same PR.

If 7.1 has already landed, that baseline moved once already — do not
assume a diff here means this change broke something; compare against
the post-7.1 baseline, not the original.

**Browser** — at 1600px: header present, content capped rather than
stretched, both cards visibly cards. Then the Copilot flow end to end
with a real key: dropdowns labelled, key field a sensible width,
"Test connection" produces a clearly-styled success and a clearly-styled
failure, and the backup card states when you last exported.

## Risks

1. **`lastBackupAt` needs somewhere honest to live.** `AppSettings` is
   the obvious home, but it is also included in the backup bundle — so
   restoring a backup would restore its own stale timestamp. Either
   exclude the field from `CvBackupBundle` or overwrite it on import.
   `backup_service_test.dart` already covers round-tripping and
   `bundleVersion` handling, so extend it rather than discovering this
   in the wild.
2. **Scope creep into a backup reminder system.** Decision on prompting
   is one prompt after first export. Scheduling, snoozing, and
   frequency preferences are a different product.

## Not in scope

Cloud sync; encrypting the stored API key (a real improvement, but it
needs a key-derivation story and a password, which the app does not
have); a settings search; theme switching.
