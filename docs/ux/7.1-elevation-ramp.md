# 7.1 — Surface elevation ramp

## Context

`app_colors.dart` line 9 reads:

```dart
const Color kcBackgroundColor = kcDarkGreyColor;
```

So the scaffold background, every `Card`, the `NavigationRail`, the
Copilot config card and the Vault editor panel are all `#1A1B1E`. Cards
are not distinguishable from the ground they sit on; the only thing
separating an `AppSummaryCard` from the page is Material's default
elevation shadow, which on a dark surface is close to invisible.

This is the single largest contributor to the app reading as flat and
unfinished, and it is also the cheapest of the six to fix — it changes
no layout and no behaviour. Doing it first means every screenshot taken
while working on 7.2 through 7.5 already looks better.

A second problem is bundled in here because it has the same cause:
`kcMediumGrey` (`#474A54`) is currently carrying three unrelated
semantic roles at 16 call sites — divider/border colour, placeholder and
disabled text colour, and the preview pane's backdrop
(`studio_preview_pane.dart`'s `ColoredBox(color: kcMediumGrey)`). One
value cannot serve all three; a border wants to be much darker than
placeholder text.

---

## Decisions locked

| # | Decision | Rationale |
|---|---|---|
| 1 | **Route surfaces through `ColorScheme`'s M3 container slots**, not new bespoke `kc*` names used directly by widgets | `buildAppTheme()` already builds a `ColorScheme` and pins four slots. M3's `Card` defaults to `colorScheme.surfaceContainerLow`, so pinning the container ramp makes `Card` correct with no widget changes — and lets `AppSummaryCard` **delete** its `color:` argument rather than change it. Fewer call sites touched, and Material-default-styled widgets stop needing per-widget overrides. |
| 2 | Keep the raw values as `kc*` consts in `app_colors.dart` | Consistent with how every colour in this project is already declared. The `ColorScheme` reads them; widgets read the scheme. |
| 3 | **No `AppSurfaces` `ThemeExtension`** | `AppSpacing`/`AppRadius`/`AppTypography`/`AppMotion` exist as extensions because Material has no slot for those concepts. Material *does* have slots for surface elevation. Adding a parallel extension would mean two sources of truth for card colour. |
| 4 | Split `kcMediumGrey`'s three roles into three named consts | A border at the same value as placeholder text means one of the two is wrong. Confirmed 16 call sites, so the split is a mechanical pass, not a redesign. |
| 5 | Dark-only, still | A light theme is not in scope and nothing here blocks one later — the ramp is the thing a light theme would need to invert, and it will exist after this. |

---

## The ramp

Four surface tiers plus two line weights. Values chosen so each step is
visible at a glance on an OLED panel without the ground going pure
black (pure black plus a purple accent produces visible fringing on
some displays, and the current `#1A1B1E` is a reasonable *middle* of the
ramp rather than a reasonable ground).

```dart
/// The page ground — behind everything, never on a card.
const Color kcSurfaceSunken = Color(0xFF101114);

/// The default panel/rail surface. This is the app's old single
/// background value, now demoted to one tier of several.
const Color kcSurface = Color(0xFF1A1B1E);

/// A card or dialog sitting on [kcSurface].
const Color kcSurfaceRaised = Color(0xFF22242A);

/// A hovered/nested card, or an inline editor inside a card.
const Color kcSurfaceOverlay = Color(0xFF2B2E36);

/// Hairline borders and dividers — was one of `kcMediumGrey`'s three
/// jobs.
const Color kcBorderColor = Color(0xFF2F323A);

/// A border that needs to read as deliberate rather than incidental —
/// a focused field, a selected card's edge.
const Color kcBorderStrong = Color(0xFF454956);
```

`kcMediumGrey` **stays**, narrowed by its doc comment to its one
remaining legitimate job: placeholder and disabled text. `kcDarkGreyColor`
and `kcBackgroundColor` are deleted; every reference moves to one of the
tiers above.

## What changes

### `lib/ui/common/app_colors.dart`

Add the six consts above. Delete `kcDarkGreyColor` and
`kcBackgroundColor`. Rewrite `kcMediumGrey`'s doc comment to state the
single role it now has, and add a file-level comment stating the ramp
invariant once — per `CLAUDE.md`'s "state a cross-cutting rationale
once" rule, this is the file that owns it and every other file should
reference it rather than restate it.

### `lib/ui/common/app_theme.dart`

Extend the existing `copyWith` on the seed-derived scheme:

```dart
surface: kcSurface,
surfaceContainerLowest: kcSurfaceSunken,
surfaceContainerLow: kcSurfaceRaised,
surfaceContainer: kcSurfaceRaised,
surfaceContainerHigh: kcSurfaceOverlay,
surfaceContainerHighest: kcSurfaceOverlay,
outlineVariant: kcBorderColor,
outline: kcBorderStrong,
```

Then `scaffoldBackgroundColor` and `canvasColor` become
`kcSurfaceSunken`, and `dividerColor` becomes `kcBorderColor`. The
existing doc comment explaining why only some slots are pinned needs
updating — it currently says "every other slot stays seed-derived,
nobody's designed a value for those yet", which stops being true for the
container family.

### Widget call sites — roughly 36, in three groups

Confirmed counts, excluding the declaring file: `kcBackgroundColor` 7,
`kcDarkGreyColor` 13, `kcMediumGrey` 16.

1. **Deletions.** `AppSummaryCard`'s `color: selected ? kcPrimaryColorDark
   : kcDarkGreyColor` loses its unselected branch entirely — `Card`
   picks up `surfaceContainerLow` on its own. Same for the `Container`
   decorations in `copilot_config_card.dart` and the error chip in
   `studio_preview_pane.dart`.
2. **Ground vs surface.** `AppChrome`'s `Scaffold(backgroundColor:)` and
   the `NavigationRail(backgroundColor:)` currently pass the same value;
   they become `kcSurfaceSunken` and `kcSurface` respectively, which is
   what gives the rail its edge without needing the divider.
   `vault_view.desktop.dart`'s `ColoredBox(color: kcDarkGreyColor)`
   around the editor panel becomes `kcSurface`.
3. **`kcMediumGrey` triage.** Every `VerticalDivider`/`Border` use goes
   to `kcBorderColor`. Every placeholder/disabled-text use stays.
   `studio_preview_pane.dart`'s backdrop is neither — a PDF page needs
   to read as paper on a work surface, so it goes to `kcSurfaceSunken`,
   darker than the panel beside it rather than lighter.

### Also worth fixing while here

`AppSummaryCard`'s selected state uses `kcPrimaryColorDark` (`#300151`)
as a full fill plus a `kcPrimaryColor` border. With a real ramp
underneath, a `kcSurfaceOverlay` fill plus a 2px `kcPrimaryColor` left
edge reads as selection without the panel turning purple. This is a
judgement call, not a defect — but it is the same file and the same
review finding, and doing it separately means re-baselining the goldens
twice.

## Steps

1. Add the consts; delete the two old names. `flutter analyze` now lists
   every call site that needs attention — use it as the worklist rather
   than grepping.
2. Pin the `ColorScheme` container slots and update `buildAppTheme()`'s
   doc comment.
3. Work the analyzer errors down in the three groups above, preferring
   deletion over substitution.
4. `stacked generate && dart format .` — the token files use
   `theme_tailor`, and generated output is not reliably format-clean.
5. Re-baseline goldens (see below). This is not optional and not a
   follow-up.

## Verification

```bash
stacked generate
dart format .
flutter analyze
flutter test --exclude-tags=golden
```

`--exclude-tags=golden` is the locally-meaningful signal; the five
baselines are rasterised on `ubuntu-latest` and will show a small
diff on Windows even with no real change.

**Goldens.** All five baselines change, because all five pump their View
inside `AppChrome`. Dispatch `update-goldens.yml`, download the
`goldens` artifact, and commit the PNGs **in the same PR**. Phase 4.1
recorded the same requirement for a nav-rail change and the reasoning
has not changed.

**Browser.** Start the preview and check the four surfaces that were
previously indistinguishable now read as separate: the CVs list (card
against ground), Vault with the editor open (list, divider, panel),
Studio (rail, config panel, preview backdrop), Settings. Compare against
the review screenshots — the specific thing to confirm is that a card
edge is visible without relying on its shadow.

## Risks

- **The ramp fights the accent.** `kcPrimaryColor` is `#9600FF` at 100%
  saturation; on a lighter `kcSurfaceOverlay` it will read hotter than it
  does today. Desaturating the accent is a real need but belongs to its
  own change — if it looks wrong at step 3, note it and move on rather
  than widening this one.
- **Seed-derived slots shifting underneath.** Pinning six container
  slots means Material widgets that previously picked seed tones now
  pick ours. Anything that looked accidentally fine may stop looking
  fine — the goldens will catch it on the three covered Views, and
  nothing catches it on Studio.

## Not in scope

Accent desaturation, the radius and spacing scale cleanups, and the
missing `body` typography role. All three are real findings from the
same review section, and all three are independent — they do not need to
ride along with a colour change that already re-baselines every golden.
